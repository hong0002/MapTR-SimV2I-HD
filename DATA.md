# Data Layout

The full SimV2I-HD dataset is not tracked in this repository. Prepare the
MapTR-format SimV2I-HD split separately, then point the code to it with
`SIMV2I_HD_ROOT`.

```bash
export MAPTR_ROOT=/path/to/MapTR-SimV2I-HD
export SIMV2I_HD_ROOT=/path/to/simv2i_hd_benchmark_v2_dynamic_rsu_20k
```

## Expected External Dataset Root

The main ACCV experiments use the 20k dynamic-RSU split:

```text
${SIMV2I_HD_ROOT}/
├── simv2i_maptr_infos_train.pkl
├── simv2i_maptr_infos_val.pkl
├── simv2i_maptr_infos_test.pkl
├── simv2i_maptr_map_gt_train.json
├── simv2i_maptr_map_gt_val.json
├── simv2i_maptr_map_gt_test.json
└── images or raw image folders referenced by the PKL files
```

The PKL files store sample metadata, camera paths, camera calibration, ego/RSU
pose metadata, and MapTR-consumable vector map annotations. The
`simv2i_maptr_map_gt_*.json` files store the same vectorized HD map ground truth
in a convenient JSON form used by visualization and analysis tools.

Do not confuse these dataset JSON files with `map_ann_file` in the MapTR
configs. `map_ann_file` points to `outputs/maptr/eval_cache/..._gt.json`, which
is a generated evaluation cache. During `tools/test.py --eval ...`, MapTR checks
whether this cache exists; if it is missing, the dataset's `_format_gt()` method
rebuilds it from the loaded split PKL and writes it under `outputs/maptr/eval_cache/`.
The cache is ignored by git and can be regenerated from `SIMV2I_HD_ROOT`.

If image paths inside the PKLs are relative, they are resolved from
`SIMV2I_HD_ROOT` when that environment variable is set. Therefore the external
dataset root should contain the image folders in the same relative layout used
by the PKLs.

## Split And Classes

The expected split sizes are:

- train: 14,000 samples
- validation: 2,000 samples
- test: 4,000 samples

The vectorized HD map classes are:

- `divider`
- `boundary`
- `ped_crossing`

The paper BEV range is:

- x in `[-15, 15]`
- y in `[-30, 30]`

The dataset is generated by the separate SimV2I-HD dataset construction
repository. Test labels should be used only for final reporting and must not be
used for model selection.

## Validation

Run the lightweight validator before training or evaluation:

```bash
cd "${MAPTR_ROOT}"
bash scripts/validate_server_maptr_data.sh \
  --dataset-dir "${SIMV2I_HD_ROOT}" \
  --require-data
```

If `SIMV2I_HD_ROOT` is exported, the wrapper also uses it by default:

```bash
bash scripts/validate_server_maptr_data.sh --require-data
```

The validator checks that the split PKLs exist, that vector-map classes are
recognized, and that referenced image paths are readable. Reports are written
under `outputs/maptr/server_setup/`, which is ignored by git.

Evaluation caches under `outputs/maptr/eval_cache/` are generated by evaluation
runs and do not need to be copied from the dataset release. To regenerate them,
remove the stale cache file and rerun the corresponding evaluation command with
`SIMV2I_HD_ROOT` set.

## Backward-Compatible Symlink Option

The public configs support `SIMV2I_HD_ROOT` directly. For compatibility with
the original experiment layout, they also fall back to:

```text
data/maptr/simv2i_hd_benchmark_v2_dynamic_rsu_20k
```

To use that fallback without copying data into the repository, create a symlink:

```bash
cd "${MAPTR_ROOT}"
mkdir -p data/maptr
ln -s "${SIMV2I_HD_ROOT}" \
  data/maptr/simv2i_hd_benchmark_v2_dynamic_rsu_20k
```

This symlink is optional and exists only for backward compatibility.
